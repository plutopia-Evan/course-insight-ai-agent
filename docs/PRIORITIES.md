# 产品改进优先级与交付状态

本轮按“调用清楚 → 结果可信 → 易于使用 → 可观测”的顺序推进。真实业务评测、运营采用与生产规模能力分别列出，不以合成样例或自动测试代替。

| 优先级 | 工作 | 已交付 | 仍需完成 |
|---|---|---|---|
| P0 | 分析结果复用与工具契约 | analysis_id、已有结果查询、报告复用、Dify 调用规则，避免取报告重复调用模型 | 将工具配置更新到实际使用的外部平台 |
| P1 | 真实质量评测基础 | 离线评分器、意见一对一匹配、分类 F1、失败与证据检查、标注规范、合成演示、明确开启真实调用的预测脚本 | 用户尚无真实测评数据；需脱敏反馈、双人标注和独立检验，才能给出真实质量成绩 |
| P1 | 输入与统计口径 | 明确学员列、重复/空编号检查、映射校验、多重匹配待确认、未知题部分结果、反馈覆盖与分母字段 | 用真实历史问卷检查兼容性与标签边界 |
| P2 | 运营流程与共享服务 | 默认映射、模板下载、合成示例、一次完成基础+可选 AI；网页与 /analysis/batch 共用分析、总结、报告服务 | 旧单文件接口维持兼容范围；外部客户端可逐步迁移批量接口 |
| P2 | 建议可执行性 | 在页面与报告增加人工审核表，展示涉及人数/分母，留出严重程度、整改成本、负责人和采纳决定 | 运营填写与验证；尚未将频率阈值宣称为最优业务优先级 |
| P3 | 成本和运行观测 | 分类/总结/显式重试的实际请求记录、耗时、token、可选估算费用、缓存记录分开显示；缺数据不伪装零成本 | 真实调用账单和压测；队列、限速与并发参数需基于实际负载设计 |
| P3 | 多人生产使用 | 保留服务鉴权和报告存储边界说明 | 多租户权限、共享对象存储、保留策略、部署和真实采用率尚未实现 |

## 验证

本轮新增或覆盖：结果复用、意见级评测、标签误判、漏拆与重复输出、映射歧义、学员编号、时间题误识别、全未知题、网页示例流程、网页与批量接口结果一致、AI 请求预算、调用记录隔离和无隐私日志。

合成演示命令见 evaluation/README.md。自动测试不调用付费模型。真实数据缺失已经明确记录，没有生成虚构的准确率或节省时间比例。

## GitHub 与部署

修改按功能分批提交到 codex/reuse-analysis-results 分支，通过 Pull Request 查看。代码上传不等于上线部署，也不自动修改 main。

## 存储边界

analysis_id 的复用依赖报告和 analyses/ 记录同时保留。当前为实例本地文件与服务级鉴权；缓存并发、跨实例共享和个人数据隔离需要在多人生产部署前继续处理。
